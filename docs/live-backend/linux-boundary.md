## Components and state

| Component | Dependency and responsibility | State / failure |
| --- | --- | --- |
| NativeSupervisor | Fixed installed launcher custody, three independent signature roles, exact signed files and kit, native adapter | One session per dedicated process; no caller context or backend argument |
| Native channel | Owned socketpair; per-message kernel credentials; pidfd, PID/start/cgroup/UID/GID/capability/namespace checks | Validate before and after blocking operations; death/EOF/cancellation invalidates handle |
| Cgroup lease | Preallocated empty root-owned cgroup-v2 leaf, finite CPU/memory/PID limits, exclusive session lock | Attach before releasing child gate; kill whole leaf, drain adopted descendants, prove populated=0 |
| Replay journal | Root-only no-follow file, exclusive flock, chained canonical JSONL, append + fsync + readback | RESERVED before child creation, RUNNING before operations, terminal only after cleanup |
| UnitSupervisor / UnitBoundary / UnitReplayStore | Explicit injected unit adapters | UNIT_VERIFICATION_ONLY, never installed authority |
| Fixed proxy successor | CONF-LIVE-003, later protected network/admission implementation | Missing module is PROTECTED_PROXY_UNAVAILABLE; no fallback |

Lifecycle:

`VALIDATED_DATA -> durable RESERVED -> containment + peer checks -> RUNNING -> COMPLETED / FAILED / CANCELLED / EXPIRED`

Terminal states have no outgoing edge. Only all ten fixed, distinct passing
operations can complete. A failed or unavailable operation closes the session;
an unavailable operation's receipt stays NOT_RUN_ENV_UNAVAILABLE. Cancellation
racing an already executing operation may end in FAILED (interrupted I/O) or
CANCELLED; neither permits reuse. Cleanup failure or clock rollback can leave
the durable record RESERVED/RUNNING **consumed**, with no fabricated terminal
receipt. Journal read errors, torn writes, uncertain fsync/readback, full storage
and custody changes all refuse execution. No truncation, repair, nonce expiry,
rotation or automatic lease recovery is implemented.

An append failure before any byte reaches storage may leave an empty journal
after process restart. That is safe only because execution never precedes a
successful durable reservation. Any complete or partial reservation survives
as consumed or as a globally refusing corrupted journal. Root/operator
tampering, disk rollback, hardware lying about fsync and hostile kernels are
outside this source candidate's trust boundary; production backup/restore must
preserve replay history and never restore a reusable old nonce ledger.

## Native boundary and custody

The production constructor accepts no path, executable, callback, module name,
storage adapter, FD, token or verified flag. It requires Linux, root UID/GID,
one thread, no preexisting children and default SIGCHLD disposition; the
module must be loaded from the exact installed launcher archive and its
independently signed root manifest must verify. The unchanged legacy launcher
continues to refuse live execution until the separately owned CONF-LIVE-006
bridge and external installation gates are complete.

The native entry also rejects ambient credentials, proxy/import variables and
open descriptors beyond nonsocket stdio. Only PATH, HOME, USER, LOGNAME, LANG,
LC_ALL, TZ and the fixed HARNESS_LIVE_EXECUTION_ENVELOPE input may be present;
none is an authorization flag. The child clears that remaining environment.
Manifest/public-key/signature/launcher bytes are read once under no-follow
custody, verified with the unchanged signature/key contract, and retained by
the dedicated process. Repeated internal native constructors use that verified
snapshot; the envelope's launcher digest must equal it.

Authority references use retained no-follow directory/file descriptors, exact
root ownership, no write bits, single-link regular files, bounded reads and
inode/metadata rechecks. The signed kit is enumerated independently, with each
file read once. It rejects symlinks, hard links, device crossings, unsupported
objects, writable files, path aliases and inventory/digest drift. No warm
checkout or ambient root filesystem is used as a kit. The source candidate's
Fixed bounds are 4 MiB/file, 64 MiB total file data, 4096 files, 8192 total
entries, 4096 entries per directory and depth 32; the release must fit these
bounds or be unavailable.
A root-owned, nonwritable `rootfs/` inside that exact signed kit is required;
there is no host filesystem fallback. Packaging/prerequisite qualification is
not supplied by this packet.

Before any child checkout or credential access, trusted setup:

1. Creates a supervisor-owned SOCK_SEQPACKET socketpair and a closed child gate;
   marks the dedicated parent a child subreaper.
2. Forks a trusted setup child and attaches it to the exclusively leased cgroup
   before releasing the gate. An ambiguous attach still requires cleanup.
3. Clears supplementary groups and creates user, mount, PID and network
   namespaces; the parent writes exact single-ID UID/GID maps to host 65532.
4. Re-arms parent-death SIGKILL after credential changes. PID-namespace init
   retains a parent pidfd to close the death-before-prctl race even when
   getppid() is zero across the namespace boundary.
5. Makes mount propagation private; recursively bind-mounts the signed rootfs
   read-only/nosuid/nodev and chroots into it. Closes all descriptors except the
   owned local channel; removes capabilities and enables no_new_privs.
6. Installs architecture-checked classic-BPF seccomp rules. Direct socket
   creation/connect/bind/listen, namespace escape, ptrace, BPF, userfaultfd,
   io_uring and pidfd_getfd paths are denied on amd64/arm64. x32 is rejected.
   clone3 returns ENOSYS; ordinary clone/fork is allowed only inside the
   PID namespace, limits and cgroup. This is a layered boundary, not a claim
   that a syscall denylist alone is a complete sandbox.
7. Reports READY through per-message SCM_CREDENTIALS. The parent checks the
   child's kernel identity, exact cgroup, distinct namespaces, mapped UID/GID,
   zero capability sets, seccomp and no_new_privs, and retains a pidfd.

SO_PEERCRED from socketpair creation is deliberately not used as post-fork
sender identity. Truncated, duplicate or unexpected ancillary messages fail;
all received SCM_RIGHTS descriptors are closed and never become authority.
Only the supervisor-created channel is used, with checks around every bounded
operation. The isolated custodian presently accepts only a fixed ping byte;
it does **not** yet execute probes or load tenant credentials.

The child uses an absolute monotonic deadline (at most 900 seconds and never
past signed expiry), recalculated before each receive so pings cannot extend
its life. Parent death kills the trusted intermediate parent and namespace
init; PID namespace teardown kills remaining namespace processes. An alive
supervisor's expiry/cancel/close path writes cgroup.kill and drains direct and
adopted children until both wait custody and cgroup emptiness are proved.
Kernel/init reaping after supervisor death is a **native qualification gate**,
not something offline mocks establish. After a parent crash, an occupied
preallocated leaf blocks the next session instead of being silently cleared.
