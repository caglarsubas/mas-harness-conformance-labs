# Clean-room parity registry

`CONF-002` records public provenance and independently authored contract vectors. It does not open, fetch, mount, execute, import, copy, adapt, translate, or hash content from a warm-source repository.

The `gitObject` values in `parity/registry.yaml` are public provenance identifiers copied from the hash-pinned Harness Onion reuse-path index. They are not content supplied to this repository and are not copy authorization. Every record remains `REFERENCE_ONLY_PENDING_PATH_REVIEW`.

An `EXACT` result means only that the packet-owned adapter produced the independently specified public-platform expectation. `UNTESTABLE_NO_DESTINATION_TARGET` is always `WARN`, never a pass. Neither state claims that warm-source bytes ran. A future byte port requires a revised `PORT_CANDIDATE`, legal approval, an exact `COPY_AUTHORIZED` mapping, and a matching `PORTING.yaml` record.

The excluded cases are cloud and billing APIs, third-party keys, public network access, warm-source execution, and mutation. The parity campaign originates `UNIT` evidence only.
